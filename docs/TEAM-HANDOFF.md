## 本轮相对原始基准已实现什么

### 税费扩展（重要：待独立复核）

原始 8 条画像严格匹配市场、产品类型、HS、原产地和日期；新加坡/澳大利亚税基与 GST 计算器已能跨产品复用，但多数产品没有可调用画像或足够完整、可核验的税率数据。本轮沿用 SG 通用普通进口、CIF 与 GST 规则，新增 25 条新加坡画像到 `data/vo-data.json`，同步 `data/vo-data.js`；匹配和能力状态在 `js/engine.js`，页面输入、复核及显示在 `js/app.js`。相对于基准，按候选和画像匹配统计 SG 39/57 小类、AU 4/57；这不是 39 种商品的最终海关归类或全面合规结论。

新增配置引用现有 SRC-168/170/171/174，包含适用日期、来源及版本信息；扩展品类汇总要求候选及非应税范围复核。HS 仍是候选；缺少原产地、日期、币种、运保、特殊估价或贸易救济等条件时不能将未知当 0；低值进口、特殊交易等继续保留阻断。2026-12-31 是数据配置窗口，不是声称法规届时失效。汇总名称是“本模型已覆盖法定项目汇总”，不是完整到岸成本。

**专业复核是继续开发和对外使用前的关键事项：**此前官方税则和新加坡海关网页在线访问返回 CONNECT 403，新画像依据沿用原仓库核验记录；新增的 SRC-168 用户提供文件已识别标题和部分税目，但尚未同官方来源在线比对哈希，也未完成逐项税率、费率、适用范围及日期核验。不要把“已有源码/测试通过”误当成官方核验完成。请尤其复核 25 条新增画像与六位或组合候选之间的关系，以及更细税则码、非应税范围、零税率适用与是否能够生成汇总。若证据不够，应收紧或禁用相关输出，而不是以零补缺口。

重点回归：SG 电热水壶、微波炉、真空吸尘器；AU 电热水壶；SG 湿式与表面清洁。后者 5 小类目前没有足够候选映射，不能直接套用吸尘器 HS，应补产品工作原理、完整商品状态、归类及官方税率依据。AU 另修复：无匹配画像或原产地非 CN，不应因优惠条件勾选产生零关税。更详细说明和逐产品×市场矩阵：`docs/PRODUCT-OPTIMIZATION.md`、`docs/PRODUCT-TAX-MATRIX.md`、`docs/product-tax-coverage.csv`。这些文档的历史进度和测试数量可能早于最新提交，以代码及本交接为准。

### 产品体验与实现入口

- 首页、项目页统一采用 `data/vo-data.json` 的 `groups`/`subcategories`（12 产品组、57 小类），首页类别由 `js/app.js` 动态渲染，图标按组 ID 映射，点击进入对应产品组。数据为项目产品研究分类，不应宣称为官方税则或统一国际法定分类。

## 用户新增要求：政策资料库与用户语言

用户看的正式页面为 https://ljh131313-a.github.io/vision-overseas-R1/policy-documents/index.html ，它可能仍是基准 main；开发时须先比较该线上版本与开发分支，基于开发分支实现，不要覆盖线上。

### 1. 政策资料库：名称与找资料体验

将“政策原文归档 · 全量”“法规原始 PDF 与哈希校验”等开发导向名称统一调整成适合企业用户的名称，如 **“政策资料库”**（最终标题可按页面信息架构微调）。页面以用户想找什么为中心：按目的地/国家、政策主题、适用产品、文件类型与关键词查找，优先展示文件名称、简短主题/适用范围、可用版本或日期和可操作的入口。沿用现有视觉风格，不重做整站；筛选或搜索只基于有实际数据的字段，不虚构适用范围。

链接优先级：已归档且法规与版本对应的 PDF → 可核验官方 PDF → 官方网页（标注“查看官方网页”）。阅读版要真实标识为网页阅读版，不能冒充官方原文；保留官方链接、版本、来源和必要适用边界。可在详情中提供版本/来源/哈希等以供追溯，但不要让 SHA-256、字节数、构建校验成为主界面核心卖点。技术验收、索引与完整校验记录写开发文档或内部详情。

盘点全部可访问资料，按国家、主题、产品适用范围与文件类型分类；保留原始文件名、内容、来源、版本和 SHA-256；校验重复文件并记录映射；不覆盖原件。不确定的日期、文件身份、适用范围及生效状态标记待核，不得补造。优先接入资料可证实且用户需要的文件；列出缺失文件和官方来源，以便用户下载补充。核对合规结果、税费依据、资料库、法规索引和报告等所有入口，避免仅修资料库列表。

### 2. 去除面向开发人员的解释，保留用户需要的事实

用户明确指出不希望在客户端展示“哈希实测一致”“队友交付物”“原始字节未改动”“本次构建实测”等实现和交付记录，也不希望出现“这些是什么/这些不是什么”大段长说明、重复的新闻非实时/法规边界告知，及“归档≠全文结构化/规则接入/现行有效”等内部实现描述。应系统审查政策资料库、新闻、研究、数据说明及有关页面：把需要追溯的详细技术内容放开发文档或按需详情；用户界面仅保留与当前操作相关、准确简短的必要提示。

对文件的真实性、版本和适用日期仍须诚实表达；对网页阅读版与官方 PDF 的区别仍须让用户能识别；不要为了简洁隐去会影响使用判断的信息。新闻只是已有来源的快照，不能改成“实时监控”“覆盖全网”或暗示自动判断法规生效。

### 3. 研究档案带入：界面简洁，但保留保护行为

用户指出 `research/index.html` 的“带入规则：只载入品牌、型号、产品小类与地区……重置税费选择……旧建议失效”“核验 2026-11-08”等长段开发式描述和标签不适合用户端。请精简为有明确行动价值的产品提示，并在确实会替换当前项目/情景时提供清晰确认：说明即将带入哪款产品、会替换哪些当前内容，以及需要用户自行核对出口版参数。

**保留实际数据保护逻辑**：只带入已知品牌、型号、小类、地区等有证据内容；充电电压不能当市电电压，Pa 吸力不能当 W 功率；清理受影响的事实和 HS/税费选择；同市场同小类切换型号也应让旧建议及快照按现有指纹机制失效。将技术细节、字段映射、测试案例与核验记录保留在开发文档；来源及日期按需可查，但不要在每张卡片上堆砌内部术语。

### 4. “数据说明”改为“上手指南”，补充项目目的与逻辑图

检查 `index.html` 中顶部 `lnkAbout`、`view-about`、返回按钮和 `js/app.js` 的 `renderAbout()`/导航状态，将用户入口和页面名称改为“上手指南”，避免仍叫“数据说明”。内容围绕用户能做什么：选择产品与目标市场 → 补充关键事实 → 查看合规初筛与待办 → 复核 HS 并视覆盖测算税费 → 查看市场动态/千问建议（按需）→ 汇总出海报告。说明产品目标是帮助企业组织出海准备，不替代最终官方归类或专业结论；缺少资料时说明下一步该补什么。

加入易读的逻辑图，优先简单静态流程图或卡片箭头，适配手机和无障碍阅读；不要只展示堆砌内部数据结构的工程图。建议另外说明“产品资料和交易条件分别影响哪些结果”“政策资料如何回到合规/税费依据”；事实确实影响的范围以当前引擎为准。首页已有四张步骤卡，应与新指南一致、避免重复长文，保持可快速进入各功能。
